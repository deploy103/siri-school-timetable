# 보안 설계

## 비밀정보 보관

- `NEIS_API_KEY`는 서버 런타임 환경변수로만 읽는다.
- 이름에 `NEXT_PUBLIC_`을 사용하지 않으며 클라이언트 코드, 응답, URL, 로그에 포함하지 않는다.
- `.env`와 로컬 환경 파일은 Git 및 Docker build context에서 제외한다.
- Dockerfile에는 키를 `ARG`, `ENV`, `COPY`하지 않는다. Compose의 optional `.env` 파일이 실행 시에만 주입한다.
- 키가 없을 때 Mock으로 자동 전환하지 않고 `NEIS_NOT_CONFIGURED` 오류를 반환해 운영 설정 누락을 숨기지 않는다.

## 입력과 외부 요청

- 모든 쿼리는 Zod로 길이, 문자, 17개 교육청 코드 allowlist, 열거형, 숫자 범위를 검증한다.
- 학교 종류가 허용된 NEIS 시간표 데이터셋 이름으로만 매핑되며 학급 조회는 고정 `classInfo`, 급식 조회는 고정 `mealServiceDietInfo` 리소스만 사용한다.
- 외부 주소는 코드에 정의된 NEIS HTTPS origin과 endpoint로 조합한다. 사용자 입력을 host나 path로 사용하지 않아 SSRF를 방지한다.
- 외부 요청은 `AbortSignal` 기반 타임아웃과 짧고 제한된 재시도를 사용한다.
- NEIS의 오류 코드, HTTP 오류, 타임아웃과 정상 빈 결과를 구분한다.

## 남용 방지와 캐시

학교 검색과 시간표·급식·음성 API에 메모리 Rate Limit이 적용되고 `429` 응답에는 `Retry-After`가 포함된다. 검색 결과는 비교적 길게, 당일 시간표는 짧게, 당일 급식은 10분간 캐시하며 동일한 동시 외부 요청은 하나로 합친다. 현재 구현은 단일 프로세스 기준이다. 여러 replica 배포에서는 공유 저장소 기반 제한 또는 API gateway 제한을 추가해야 한다.

기본값에서는 위조 가능한 전달 헤더를 무시하고 모든 미식별 요청에 보수적인 공용 제한 창을 적용한다. `TRUST_PROXY_HEADERS=true`일 때만 구문 검증된 `X-Forwarded-For`/`X-Real-IP`를 클라이언트 키로 사용한다. 이 옵션은 인터넷에 직접 Node 포트를 노출할 때 켜지 말고, 신뢰 가능한 reverse proxy가 외부 전달 헤더를 제거·덮어쓰는 환경에서만 켠다.

## 오류와 로그

클라이언트에는 정해진 오류 코드와 한국어 안전 메시지만 반환한다. 원본 예외, 스택, upstream 본문과 키는 반환하지 않는다. 서버 로그는 요청 URL이나 헤더 대신 오류 분류와 안전 메시지만 기록한다. 예상하지 못한 오류는 일반 문구로 축약한다.

## 브라우저 및 컨테이너

전역 보안 헤더는 frame embedding, MIME sniffing, 불필요한 브라우저 권한과 임의 외부 연결을 제한한다. CORS 허용 헤더를 추가하지 않아 브라우저의 same-origin 정책을 유지한다. Compose 컨테이너는 비루트, read-only root filesystem, capability 제거, `no-new-privileges`로 실행된다.

## 공개 음성 URL

음성 URL은 인증 URL이 아니다. 포함되는 학교 코드·학년·반은 비밀로 취급되지 않지만 개인의 소속 정보가 될 수 있다. 링크를 안 사람은 같은 시간표 문장을 요청할 수 있다. 개인정보나 인증 토큰을 URL에 추가하지 말아야 하며, 서비스는 요청 빈도를 제한한다.

## 보안 문제 신고 범위

다음 문제는 보안 이슈에 해당한다.

- NEIS API 키 또는 서버 환경변수 노출
- 입력 검증/URL 조합을 우회한 SSRF
- Rate Limit의 실질적 우회 또는 서비스 거부 취약점
- XSS, 응답 분할, 민감 로그
- 컨테이너 권한 상승이나 공급망 설정 문제

실제 비밀값이나 재현 가능한 공격 코드를 공개 이슈에 올리지 말고 저장소 관리자의 비공개 보안 신고 채널로 전달한다. 단순한 NEIS 데이터 누락, 시간표 최신성, Apple 음성 인식 오차는 일반 버그 범위다.
